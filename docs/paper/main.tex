\chapter*{摘\quad 要}
\addcontentsline{toc}{chapter}{摘要}
大学生在答辩准备过程中通常能够修改文稿，却难以在缺少实验室、固定评委和专用设备的条件下持续获得结构化反馈。本文设计并实现一个面向个人训练的多端AI答辩教练SpeechMirror。系统以用户上传的论文、演示文稿、文档、文本和图片为知识边界，通过材料解析、光学字符识别、分块检索和大语言模型生成评委问题；通过移动端本地视频录制、临时音频识别和端侧派生视觉指标形成内容、表达、时间、视觉与问答五类报告。内容评价必须回链材料片段，避免用不可解释的总分替代证据。

系统采用Flutter构建iOS与Android客户端，使用ArkTS与ArkUI构建HarmonyOS 6原生客户端，后端采用Rust、Axum、SeaORM与SQLite WAL。端侧推理核心以C++稳定ABI封装，并预留MindSpore Lite接入。原始视频不离开终端，音频临时上传后删除，服务端只长期保存转写、报告与结构化指标。HarmonyOS实现用于验证核心能力在我国自主移动操作系统生态中的迁移与适配，降低单一平台依赖，而不作无法证实的知识产权归属表述。

当前工程已完成账号、项目、五类材料入口、任务队列、知识库、训练会话、ASR接口、可解释报告、AI评委、趋势接口、Flutter工作流、HarmonyOS原生工程骨架、容器化部署与论文构建链。真实AI闭环、HarmonyOS媒体管线、模型实机性能和用户可用性结论仍需在相应资源到位后验证。本文给出可复现的测试方案、数据记录表和验收条件，以保证后续结论来自真实运行而非演示数据。

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
SpeechMirror is a personal AI-assisted defense rehearsal system for university students. It grounds questions and content feedback in user-provided papers, slides, documents, text, and images. Mobile clients keep raw video on device, temporarily upload audio for speech recognition, and submit only derived visual metrics. The server combines material ingestion, retrieval, transcription, explainable reporting, and jury-style follow-up questions through provider-neutral interfaces.

The implementation uses Flutter for iOS and Android, native ArkTS and ArkUI for HarmonyOS 6, and Rust with Axum, SeaORM, and SQLite WAL for the backend. A shared C++ ABI defines observable edge metrics and reserves a MindSpore Lite adapter. The HarmonyOS client is treated as a native portability and privacy validation target rather than a web wrapper. Results that require provider credentials, licensed models, device hardware, or participant studies are explicitly withheld until measured.

\noindent\textbf{Keywords:} defense rehearsal; retrieval-augmented generation; edge-cloud collaboration; HarmonyOS; privacy; explainable feedback
