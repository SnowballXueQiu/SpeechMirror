# SpeechMirror 答辩资料库

本目录把“评什么”和“项目是什么”分开。比赛规则、答辩研究和经验分享只用于约束评委的提问方式；用户上传的论文、PPT、文档、图片和现场转写才是判断项目事实的唯一依据。

## 资料分层

| 层 | 内容 | 是否可以证明项目事实 | 用途 |
|---|---|---:|---|
| `competition_criteria` | 用户提供的华北五省计算机应用大赛答辩指标 | 否 | 决定维度、权重和作品类关注点 |
| `defense_methodology` | 用户提供的国内外答辩研究、评分 rubric | 否 | 决定如何追问、如何解释缺口 |
| `experience_reference` | 公开的学生/答辩秘书流程分享 | 否 | 只补充流程节奏和常见准备动作 |
| `project_knowledge` | 当前项目上传材料及人工修正文本 | 是 | 生成问题、证据和内容评分 |
| `presentation_transcript` | 本次现场陈述和回答转写 | 是（仅代表本次说法） | 判断覆盖、遗漏、矛盾和表达表现 |

经验材料永远不能替代项目材料，也不能把“常见问题”直接变成当前项目的问题。云端提示词见 [`cloud_jury_prompt.md`](cloud_jury_prompt.md)，检索与证据约束见 [`retrieval_schema.md`](retrieval_schema.md)。

## 已实现的后端约束

- 检索结果在送入模型前按句号、问号、分号和换行拆为完整语义单元。
- evidence.quote 必须是当前项目材料中的连续原文，并在服务端再次校验。
- 模型生成的问题如果与证据没有关键词交集会被丢弃，随后使用按类别区分的保守问题，而不是 chunk 前缀模板。
- 生成新场次时会读取同一项目近期历史问题，将相同事实的近似改写视为重复；当前场次的变化只在有材料证据支撑时接受。
- 回答评价要求输出预期要点、已覆盖要点、缺失要点和无依据说法。
- 回答分数同时受问题相关性、材料证据交集和要点覆盖限制；长篇空泛回答不会自动得到高分。
- fallback 反馈必须指出具体材料事实、缺少的验证或边界，并给出可直接补充的动作。

## 资料使用边界

压缩包中的文件名、来源和归纳结论记录在 [`sources.md`](sources.md)。原始压缩包不提交到仓库，避免把第三方全文和个人材料混入产品运行时。论文只引用可核验的规则/论文；经验分享在论文中只能标为“公开经验性材料”，不能当成正式评分标准。
